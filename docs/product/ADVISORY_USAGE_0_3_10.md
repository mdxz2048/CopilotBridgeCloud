# 0.3.10 使用限制改为提示

当前阶段不再按账号/设备/套餐 RPM、并发、周期 Token/Credit/RMB 限额或余额拒绝模型生成。模型输出仍遵循模型能力和用户 max_output_tokens；平台传输大小、超时、认证、设备授权、服务周期与模型权限不变，供应商自身限制仍可能拒绝请求。

历史 METERING_ERROR、UNRATED、UNPAID 不影响当前或新会话。正常可靠用量仍按锁定费率结算；余额无法覆盖整笔消费时保存 UNPAID 与实际待结算金额，不伪造已扣款或供应商成本，也不阻断生成。钱包仍保持非负，既有未结算记录不会因充值自动追扣，管理员可在用户财务中查看。

账号余额为零时 App 提示余额不足、当前仍可使用。用户管理展示待核对记录数、待结算记录数和金额；管理员主动锁定/解锁用户，锁定状态由服务端鉴权执行，App 展示账号已锁定与联系管理员提示。锁定影响后续请求，不取消已进入生成的请求；解锁后可刷新恢复。

管理员人工增加余额原本即在单一数据库事务中即时入账，不需要另一名管理员审核。保留权限校验、CSRF、幂等与审计，后台明确显示充值即时生效、无需审核。计费核对是异常用量审计，与充值无关。

客户端断开不再统一标记为 GATEWAY_TIMEOUT。取消请求保留用量未知事实，不会自动冻结账号。旧异常记录无需删改即可恢复正常请求。

验收：App 195 项测试；Cloud 单元 119 项（首次一个启动测试在本机并行运行时超时，单独重跑通过）；独立真实 PostgreSQL 22 项；Web 15 项。新增回归覆盖旧 RUNNING 超并发、零周期额度、零余额与历史计费异常同时存在的新会话成功；管理员锁定拒绝、解锁恢复；充值即时入账、重试不重复充值。浏览器验收使用真实组件与合成 API/IPC，不等同于官方宿主网页任务验收。

## 用户管理

主界面仅保留状态（正常/锁定）、余额增加/减少、套餐类型、模型多选、设备列表与最大设备数。异常核对、流水、邀请和历史记录折叠到更多记录。所有管理操作保留权限、CSRF、幂等和审计。

每用户最大设备数保存于 user_devices:<userId>，无需数据库迁移；登录新设备与恢复设备均按有效上限检查，减少上限不自动撤销已授权设备。账号读取作为签名设备心跳，最多每分钟写入一次活动时间；在线指最近 5 分钟活动，不代表持续连接。

余额减少不能超过现有余额，不产生负钱包。套餐选择仅展示后台可开通的 STANDARD/PRO/PAYG/QUARTER，与现有开通流程一致。套餐保存会开通新周期；已有同套餐不重复开通。更换套餐后管理员仍可调整模型权限。
