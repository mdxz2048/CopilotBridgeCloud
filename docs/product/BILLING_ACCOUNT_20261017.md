## 记账口径

复用既有模型扣款事务，原子增加单设备累计实际扣款。只在同一设备 APP_LOGIN/APP_START/APP_RECONNECT 上线边界锁计数器并保存一条上一区间汇总；WEB_LOGIN 不切分 App 区间。按实际扣款归集（流式请求在下次上线后完成的扣款归入后一区间），只计真实扣款，不计充值、奖励过期、未扣到的欠款或 SHADOW 计量。区间结算不再次扣钱包。

新上线边界与扣款对计数器行加锁，避免并发漏计、重复或跨设备混算；已有启动 sessionId 去重保留。最后开放区间不显示实时金额，等待下次上线结算。旧用量一次性按设备回填为“历史消耗汇总（未按上线区间拆分）”，不伪造旧上线时段。列表读取汇总与非 USAGE 钱包流水，分页，不启动轮询或逐请求历史聚合。保留当前计费凭据与审计记录。

## 并发与切换约束

结算锁序为请求 → 设备 key-share → 钱包 → 设备账单计数器；登录/恢复上线先锁设备再推进计数器，避免外键检查和上线写锁交叉等待。原始扣款、用量与计数器更新在同一事务中；计数器失败整笔回滚。首次迁移需短暂停止旧 API 写入，再回填已扣款历史并启动新 API；上线汇总不改钱包余额。新增派生记录在管理员实际删除账号/设备时级联清理；用户“清空登录”不物理删除任何记录。
