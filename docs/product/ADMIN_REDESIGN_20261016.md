# 后台管理优化：产品与 UI 定稿

日期：2026-10-16。范围：Cloud API、Web、必要的数据记录与协议文档；App 不修改、不上传安装包。产品 Agent 与 UI Agent 已共同确认方案，设计确认后实施。

## 1. 模型与连接

默认显示“已启用（数量）”，另设“未启用（数量）”。一张主表按模型展示：模型名称与 ID、累计请求数、输入/输出 Token、用户扣款、上游成本及覆盖笔数、上游账户余额、模型与上游状态、最近检测时间、检测及管理按钮。小屏允许表格容器横向滚动，数字右对齐，不压缩到不可读。

定价倍率、Token 价格、连接凭据、启停及高级实例排序收进模型管理弹窗。复用现有能力与权限，不自动创建费率、扩大用户权限或启用实例。主页面撤去长篇连接配置卡和分散实例编辑卡。

统计沿用 usage_events，累计口径一致，排除 @example.test 内部测试账号。缓存输入是输入 Token 的子集，不重复加总；用户扣款为实际钱包扣款，不称现金收入。成本保留实际/估算来源和已知成本覆盖数；未知不得写成 0。上游余额属于共享账户，模型行应注明共用，不能按模型累加。无余额接口显示未知。

模型启用、上游配置、上次真实能力检测分开呈现。凭据存在或目录可访问不表示生成已验证；检测沿用少量真实付费请求，按钮说明消耗上游余额、不扣用户钱包，不自动轮询付费探测。展示检测时间与错误原因，过去检查通过不是实时连通保证。

## 2. 固定侧栏

桌面后台外壳使用 100dvh，外层不滚动。侧栏品牌、账户及退出固定可见，导航自身在高度不足时滚动；右侧内容独立滚动。桌面侧栏约 242px，1050px 以下约 205px，沿用现有设计系统。弹窗正文可滚动、关闭及保存操作可达。

## 3. 活动与通知

同页两块清晰区域：活动摘要与开关、可折叠规则；通知列表与单条编辑器。桌面通知左列表右编辑，760px 以下上下排列。列表显示标题、显示/隐藏状态，选中后编辑标题和正文。保留最多 10 条及现有长度限制。

底部统一保存条显示未保存、保存中、已保存。新增、隐藏、删除均先成为草稿，保存成功才生效；失败保留草稿。保持 revision 并发冲突保护、管理员鉴权、CSRF 与审计。活动奖励开关与活动广播显示开关独立，不改变现行首次充值双方各 5 元、到账 7 天规则。离开草稿应提醒，不能静默丢弃。

## 4. 失败反馈

服务端删除成功后本地移除对应行并减总数，保留筛选、滚动、其他行与页面框架。仅当前末页变空且有前页时请求前页，不以整表 loading 闪烁。失败保留原行并显示错误；重复点击受控。

## 5. 操作记录与上线记录

操作记录设“管理操作”“上线记录”两个标签。上线定义：网页登录成功、App 设备登录成功、已鉴权设备在距上次心跳至少 5 分钟后恢复。每 5 秒正常轮询不写事件；并发恢复需防重复。失败登录、未鉴权设备和伪造请求不得记为成功上线。

展示北京时间、用户邮箱、来源、设备名称、系统与 App 版本、IP。地址仅采用服务端受信任代理配置下的 req.ip，不直接相信任意 X-Forwarded-For，不新增地理位置查询。网页设备信息只取必要的浏览器/系统摘要，不保存完整请求头或令牌。仅管理员可查看；上线记录不能命名为当前在线。历史没有事件时说明从本次上线后开始记录，不回填伪造历史。

## 6. 网站统计

恢复可见“网站统计”导航，优先复用已有 AdminInsights。展示页面浏览次数、客户端安装包下载请求数、注册用户、设备指标，以及页面明细、客户端版本/平台明细。设备指标必须明确在线或累计口径，不把设备总数标成活跃设备。

PV 沿用现有最近 30 天公开页面成功上报数据，按 UTC 日期聚合须标注，不称独立访客或人数。下载请求数为已发布客户端安装包有效 GET、文件存在且服务端开始返回文件的次数；排除 HEAD、404 和缺文件。重试、更新下载分别计次，不能称下载完成或安装人数。仅从本次功能上线起计数，不推算历史。下载统计故障应被记录且不能阻断原下载链路；不新增访客身份追踪。

## 7. DeepSeek 清理边界

生产只读核对：保留 deepseek-flash（启用，1391 条既有计量历史）；deepseek-chat、deepseek-reasoner、deepseek-v4-pro 已停用、已归档，usage_events 与 usage_records 均无记录，但仍残留实例。

仅清理以上三条旧 DeepSeek 逻辑模型及其无历史配置关联。事务内重新检查 usage_events、usage_records、ai_requests、model_sessions、实例关联及费率/账本引用，再决定物理删除；有引用则保留历史与归档状态并报告，不能级联删除历史。清理权限、实例及模型倍率/归档配置时限定已核验 ID，不使用宽泛 DeepSeek 前缀批量删除。Flash、GPT 未启用模型、凭据、供应商、用户余额和账单均保留。现有普通删除接口的归档语义不应被本次一次性清理悄悄改成全量硬删除。

## 8. 实施分工与验收

- Root：API 统计与上线事件、下载计数、模型统一管理组件、上线/网站统计组件、后台页面集成、数据清理、协议同步、统一测试部署。
- UI Agent：独占 apps/web/components/app-shell.tsx、apps/web/app/styles.css、apps/web/components/engagement-manager.tsx、apps/web/components/failure-feedback.tsx，负责布局及交互验收。
- 产品 Agent：独占本文档；只读审查新增 API、组件、测试与协议缺口，不执行生产写入或提交。

验收以真实 Web renderer 为准：1440/1000/480 宽度、长邮箱/金额/通知、键盘焦点、加载/空/失败/保存冲突均可用，退出常驻，只有目标区域滚动。后台与公开接口管理员权限分离；公共下载不受新增日志故障影响。活动修改不改变邀请账务规则，模型调整不改历史费率和钱包。独立 PostgreSQL 实际运行新增数据库集成测试，不把 skip 算通过；API/Web 类型与构建、相关单元和合同漂移检查通过后上线，并核对生产源码及指标。真实模型检测与模拟 UI 验收分别报告。
