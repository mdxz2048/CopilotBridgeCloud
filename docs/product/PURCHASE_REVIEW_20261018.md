# 购买审核与邀请奖励（2026-10-18）

状态：已完成开发、上线、App 发布与公开下载验收。

## 用户操作

1. 在 App 或网页的“我的账号 → 充值”，用闲鱼扫描个人主页二维码，购买远程学习服务。
2. 付款后点击“已支付，提交订单号”。
3. 手机扫描专属二维码，在绑定账号的网页填写订单号。手机网页不要求重新登录，也不收集金额。

管理员在“订单审核”中核对闲鱼订单号、付款状态和实付金额，填写金额并确认到账。10 / 20 / 50 元按需购买，实付金额按 1:1 增加正常余额；提交后预计 10 分钟内审核。超时仅标记，绝不自动到账。未通过需填写原因；用户核对后可以重新提交。App 与网页共享订单记录与进度。

支付提示使用简短中文和 1. 2. 3. 步骤，不引导用户在闲鱼发消息、发送邮箱或添加管理员。原微信加管理员充值界面已替换。

## 边界与账务

- 未登录不能生成二维码、查订单或使用 Cloud；恢复自己的原账号不依赖 Cloud 登录。
- 二维码链接以随机 256-bit 短期票据绑定当前用户和发起设备/网页会话，10 分钟有效。服务端只存 HMAC，令牌放 URL fragment，兑换后清除。手机获得 HttpOnly、SameSite=Strict、限定 API 路径的提交 Cookie。
- 手机 GET / POST 同时核对 X-Purchase-Ticket，防止多标签页换 Cookie 后误投另一个账号。重新生成废弃同来源未提交的旧票据；会话退出、设备撤销/密钥版本改变、账号停用均使票据失效。
- 订单号全局唯一，跨用户重复提交不泄露其他用户信息。并发申请锁、审核行锁、不可变余额流水和唯一 idempotency key 保障只到账一次。
- 正常余额、双方奖励、奖励通知、审核和审计记录在同一数据库事务内提交；任一失败整体回滚。
- App 控制请求限时 15 秒，IPC 有上限；网页 API 包括响应体也限时 15 秒。写入超时提示刷新确认结果，不自动重放。

## 邀请奖励（取代旧手动加余额触发规则）

仅在活动期间通过邀请注册的新账号，首次购买并经管理员审核正常余额到账后，双方各得 ¥5 奖励，到账后 7 天有效。注册、手动增减余额、赠送、仅开通套餐、重复审核都不触发。异常邀请保留人工核对；核对也必须已有有效的已审核购买。

奖励发放时分别建立双方的持久通知。App 和网页登录后弹出“邀请奖励已到账”，需点击“确认到账”。刷新、重开、Esc 都不确认；服务端按用户保存确认状态，确认请求幂等。余额已到账，确认是阅读回执，不是第二次领款。历史已发奖励不追回，不追补弹窗。

- PostgreSQL 隔离数据库：订单绑定/权限/CSRF、票据失效、设备签名、跨标签页、并发重复提交和审核、精确金额、未通过重提、超时标记、余额回滚、双方奖励及确认归属。
- 界面：真实 React 组件和合成 API，App 浅色/深色、网页、390px 手机、后台金额初始为空、失败释放按钮、奖励刷新/Esc/明确确认。

闲鱼订单金额仍由管理员人工核对；不声称自动对接闲鱼支付。
